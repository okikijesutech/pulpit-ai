# Architectural Decision Records (ADRs)

## ADR-001: Runtime Stack Selection (Electron + TypeScript + Native whisper.cpp)
* **Date:** 2026-11-01
* **Status:** Confirmed & Approved
* **Context:** Target hardware is an HP EliteBook 840 G3 (Intel Core i5-6300U, 2 cores / 4 threads, 8 GB RAM, 11.04 GB free SSD storage on Windows 10 Pro).
* **Decision:** Selected Option 2 (Electron desktop shell with native C++ `whisper.cpp` worker subprocesses and SQLite FTS5) over Option 1 (Python/FastAPI) and Option 3 (Rust/Tauri).
* **Rationale:**
  * Python + PyTorch requires 3–5 GB of disk space (which would exhaust the 11 GB available) and consumes 1 GB baseline RAM.
  * `whisper.cpp` compiled with AVX2 runs in < 200 MB disk space and 150–350 MB RAM for quantized models (`base.en-q5_1`).
  * Separate OS processes ensure fail-closed crash isolation.

## ADR-002: FreeShow State Observability and Authority Guard
* **Date:** 2026-11-01
* **Status:** Confirmed & Approved
* **Context:** FreeShow does not provide synchronous pre-event hooks to intercept manual operator clicks inside its GUI.
* **Decision:** Pulpit AI does not attempt to lock or hijack the FreeShow UI. Instead, the Central Authority Manager controls Pulpit AI's internal dispatch channel and revokes AI projection permissions instantly when manual activity or connection instability is detected.

* **Date:** 2026-11-01

* **Context:** Modern Bible translations and contemporary worship lyrics are protected by copyright law and cannot be bundled in open-source distributions.

## ADR-004: Removal of Unsafe Presentation Defaults, Synthetic Timers, and Test Hooks
* **Date:** 2026-11-03
* **Status:** Confirmed & Approved
* **Context:** Initial prototypes used fallback default references (`John 3:16`, `43.3.16`), hardcoded authentication keys (`1445`), a 300ms synthetic timer falsely claiming command success, and development mocks that could leak into live audio inference or production builds.
* **Decision:**
  * Reject commands lacking an explicit, validated scripture reference (`success: false`). Never default to John 3:16 or any other verse.
  * Emit presentation commands exactly once per operator approval.
  * Require verified confirmation: directly via socket callback or by observing matching output events on FreeShow's broadcast channel. If unconfirmed after 1200ms, report fail-closed status `sent_unconfirmed`.
  * Read authentication credentials from operator configuration or detect them from local settings; never hardcode credentials.
  * Forbid automatic startup of `MockFreeShowServer` in production builds (`app.isPackaged || NODE_ENV === 'production'`). In dev, visibly display a persistent `SIMULATED` banner and `FreeShow: SIMULATED` status.
  * Restrict audio simulation test rigs behind development mode and clear mock registers immediately upon use to protect live microphone inference.
  * Disk space checks in `ModelManager` fail closed when filesystem stats throw errors.

## ADR-005: Candidate Approval by ID and Server-Side Registry (PR 3)
* **Date:** 2026-11-03
* **Status:** Confirmed & Approved
* **Context:** In early iterations, the renderer passed the entire suggestion payload object over IPC to `authority:approve-candidate`. A compromised renderer or forged IPC payload could submit arbitrary presentation actions and bypass AI verification. Furthermore, candidates lacked replay protection and lifetime bounds.
* **Decision:**
  * Candidates generated by AI engines are stored exclusively in the main process `CandidateRegistry` in `AuthorityManager`.
  * `authority:approve-candidate` strictly accepts a `candidateId: string`. Passing an object or un-registered ID is rejected fail-closed and logged as a security alert.
  * Suggestion approvals are strictly single-use; replay attempts are rejected.
  * Candidates carry an automatic 2-minute (120-second) expiry window.
  * Manual Lock active state unconditionally blocks approval of any candidate.

## ADR-006: Full Bible Data Acquisition and Cryptographic Fail-Closed Verification (PR 4)
* **Date:** 2026-11-03
* **Status:** Confirmed & Approved
* **Context:** Early prototypes embedded a small 55-verse TypeScript seed file (`SeedScriptureData.ts`). In production church use, this resulted in missing verses for legitimate sermon references outside the sample set. Furthermore, Scripture datasets required tamper-evident cryptographic verification to ensure biblical integrity.
* **Decision:**
  * Sourced the full 66-book Protestant Canon (1,189 chapters, 31,102 verses) from official eBible.org VPL datasets for both the World English Bible (WEB, 2020 Revision) and the King James Version (KJV, 1769 Oxford Standard Text).
  * Converted verses out of TypeScript code into versioned JSON data files (`web.json` and `kjv.json`) stored in `packages/scripture-engine/data/`.
  * Assigned authentic SHA-256 cryptographic checksums to each package metadata (`metadata.checksum` calculated over `JSON.stringify(verses)`).
  * Implemented fail-closed loading in `ScriptureDatabase`: during startup, package checksums are computed and compared against `metadata.checksum`. Any checksum mismatch or missing checksum immediately throws and refuses to register the translation or insert verses into storage.
  * Confirmed public domain licenses: WEB dedicated to Public Domain by Michael Paul Johnson; KJV 1769 Oxford Standard Text in Public Domain worldwide.
  * Reserved the 55-verse `SeedScriptureData.ts` exclusively for isolated, fast unit tests. All desktop startup and production workflows load the verified full Bible data files.

## ADR-007: Scripture Parser Guards, Cue Requirements, and Rolling Window Rules (PR 5)
* **Date:** 2026-11-04
* **Status:** Confirmed & Approved
* **Context:** In live preaching, colloquial speech patterns frequently collided with biblical book names and numbers (e.g., "mark 10 times" or "job 2 weeks ago" spuriously suggested Mark 10:1 or Job 2:1). Whole-chapter citations silently defaulted to verse 1 instead of presenting the chapter accurately. In multiline utterances, only the first reference was parsed. Additionally, subsequent conversational phrases (e.g. "Amen church", "Praise the Lord") caused the rolling window to re-parse and re-emit old references after the 10-second cooldown expired.
* **Decision:**
  * Require a structural or spoken cue for bare numbers (a colon `:`, `"chapter"`, `"verse"`, or explicit phrases such as `"turn to"`, `"open to"`, `"read from"`).
  * Cue-less matches receive lower confidence and a `needsReview: true` flag. Non-scriptural unit words (e.g. "times", "weeks", "days", "years", "percent") immediately reject matches.
  * Whole-chapter results are explicitly labeled as `"whole chapter, no verse given"` and retrieve all chapter verses, never silently defaulting non-Psalm books to verse 1.
  * `ScriptureReferenceParser.parseAll()` scans and returns all explicit references found within a segment.
  * Encapsulate rolling context window processing in `ScriptureCandidateGenerator.processUtterance()`. Re-parse the rolling window ONLY when the newest segment adds a book or number, preventing old references from re-triggering after cooldown expiry on conversational words.
  * When a rolling utterance refines a whole-chapter suggestion (e.g. "John chapter 3" followed by "verse 16"), the specific verse candidate supersedes the whole-chapter suggestion, ensuring a single final candidate.

## ADR-008: Real Audio Capture, AudioWorklet Threading, and Hardware Disconnect Guards (PR 6)
* **Date:** 2026-11-04
* **Status:** Accepted
* **Context:**
  * Audio capture previously relied on a hard-coded device list in `AudioDeviceManager`, deprecated `ScriptProcessorNode` running on the main UI thread (causing buffer dropouts and missing words during React renders), synthetic level meter timers that broadcast fake background noise in `main/index.ts`, and browser DSP (`echoCancellation`, `noiseSuppression`, `autoGainControl`) that aggressively muffled preaching vocals.
* **Decision:**
  * **Dynamic Hardware Enumeration:** Device discovery queries `navigator.mediaDevices.enumerateDevices()`, filtering strictly for `audioinput`.
  * **Acoustic DSP Bypass:** Set `echoCancellation: false`, `noiseSuppression: false`, and `autoGainControl: false` in `getUserMedia` to acquire raw, natural acoustic dynamics for church speech and worship singing.
  * **AudioWorklet Architecture:** Migrated capture from deprecated `ScriptProcessorNode` to a dedicated `AudioWorkletNode` running `PcmCaptureProcessor` in the audio rendering thread with zero-copy buffer transfer.
  * **Hardware Disconnect Detection (< 1s):** Handled `track.onended` and `navigator.mediaDevices.ondevicechange` to transition to an explicit `NO AUDIO` / `'disconnected'` state within 1 second.
  * **Switch Flush:** Switching input sources immediately flushes pending frames from `SpeechSegmenter` via `flush()`, avoiding cross-source audio leakage.
  * **Synthetic Meter Removal:** Removed fake background noise timer from `main/index.ts`. Real level meter explicitly distinguishes `muted` (`MUT`), `silent` (`SIL`), `active` (dBFS), and `disconnected` (`OFF`).

## ADR-009: Native Speech Engine, Cryptographic Model Integrity, and Phantom Phrase Filtering (PR 7)
* **Date:** 2026-11-04
* **Status:** Accepted
* **Context:**
  * Speech-to-text inference previously used simulated mock inference or lacked external process boundaries.
  * Model files lacked authentic cryptographic checksums and size records.
  * Whisper models frequently hallucinate polite closing phrases (`"Thank you."`) or musical indicators (`"[MUSIC]"`) during ambient pauses in sanctuary acoustics.
  * Confidence scores were artificially hardcoded (e.g., `0.94`, `0.92`) rather than reflecting real inference probability.
* **Decision:**
  * **Native Subprocess Inference:** Execute speech inference strictly outside the Electron main process via a dedicated native `whisper.cpp` / `whisper-cli` worker process.
  * **Official Model Checksums & Size Verification:** Record official SHA-256 hashes and exact byte sizes for `tiny.en-q5_1`, `base.en-q5_1`, and `small.en-q5_1`. Stream and verify hashes with fail-closed rejection on mismatch.
  * **Gated Model Downloads & Disk Space Verification:** Prohibit automatic/silent network downloads. Require explicit operator authorization (`requestDownloadPermission`) with a mandatory >= 2 GB safety margin check on target storage before initiating any download.
  * **Phantom Phrase Interception:** Introduce `PhantomPhraseFilter` to detect and discard hallucinated bracketed tokens (`[MUSIC]`, `[BLANK_AUDIO]`, `[applause]`), repetitive subtitle/credit tags (`Subtitles by...`), and ambient noise loops (`Thank you.`) before they reach transcript feeds or scripture parsers.
  * **Real Confidence Reporting:** Model transcripts must carry actual token confidence or `null` (`confidence: number | null`). Remove synthetic scores; the UI renders `—` when confidence is unavailable.
  * **Canonical Prompt Seeding:** Prime `whisper.cpp` with a canonical prompt containing all 66 Protestant canon books and sermon cues ("chapter", "verse", "turn to") to bias beam search toward correct biblical terminology.
  * **Packaging & Binary Distribution:** Configure `electron-builder.json` `asarUnpack` to unpack native binaries and models (`bin/**/*`, `@pulpit-ai/speech-engine/bin/**/*`, `@pulpit-ai/speech-engine/models/**/*`) so they execute cleanly in packaged environments. Align UI labels to `"whisper.cpp (AVX2)"`.

## ADR-010: Adaptive Noise Floor VAD, Pre-Roll Ring Buffer, Boundary Overlap & Singing Separation (PR 8)
* **Date:** 2026-11-05
* **Status:** Accepted
* **Context:**
  * Fixed-threshold voice activity detection either cut off quiet phrases or triggered false speech detections on sanctuary HVAC and room hum.
  * Absence of a pre-roll buffer clipped initial word consonants and plosives (e.g. "p", "t", "th") before VAD triggered.
  * Pauses following biblical book names (e.g., "Turn with me to John" ... pause ... "chapter 3") caused premature utterance cuts that split book names from chapters and verses.
  * Singing during worship service was pushed into the speech path, causing Whisper hallucination loops and CPU exhaustion.
* **Decision:**
  * **Adaptive Noise Floor VAD:** Implement continuous ambient noise tracking in `VoiceActivityDetector` that dynamically shifts the speech threshold above ambient room noise (`threshold = max(minThreshold, noiseFloor * 1.8)`), bounded between `0.001` and `0.035`.
  * **Pre-Roll Ring Buffer:** Utilize `AudioRingBuffer` to maintain a volatile 200–300 ms (default 250ms = 4,000 samples) pre-roll buffer in RAM, prepending it to utterances when speech starts to preserve initial consonants.
  * **Trailing Book Boundary Overlap & Extension:** When Whisper recognizes a biblical book name near the end of an utterance, `SpeechSegmenter` extends silence hangover by 15 frames and flags a 1.5-second trailing overlap, prepending the book name audio into the subsequent utterance so the citation is preserved intact.
  * **Singing Separation:** Modeled via `SingingActivityDetector`. When singing is active (`mode === 'singing'`), frames are diverted away from `SpeechSegmenter`, and in-progress speech is cleanly flushed, keeping worship singing separate from speech recognition.
  * **Pipeline Reconciliation:** Reconciled `AUDIO_PIPELINE.md` with real parameters (0.5s min, 6.0s max, 450ms hangover, 250ms pre-roll, 1500ms overlap).

## ADR-011: Audio Fixtures, End-to-End Pipeline Integration, and Benchmarking (PR 9)
* **Date:** 2026-11-05
* **Status:** Accepted
* **Context:**
  * Testing previously relied on individual module unit tests or mocked inputs without end-to-end WAV audio clips representing real church acoustics.
  * Objective quality benchmarks (Word Error Rate, scripture reference precision and recall, false-positive suggestion rate, and processing latency) were not automated.
* **Decision:**
  * **Calibrated WAV Fixtures (`tests/fixtures/`):** Maintain standardized 16-bit 16kHz mono audio clips with `manifest.json` metadata covering:
    - Accented preaching with spoken scripture citations (`preaching_accented_john316.wav`, `preaching_accented_romans828.wav`)
    - Quiet sanctuary preaching (`preaching_quiet_psalm23.wav`)
    - Noisy preaching speech with room HVAC hum (`preaching_noisy_matthew53.wav`)
    - Sustained choir singing (`choir_worship_amazing_grace.wav`)
    - Sustained instrumental pad/organ chords (`instrument_organ_pad.wav`)
    - Ambient room silence (`ambient_silence.wav`)
  * **End-to-End Integration Suite (`tests/WavToCandidate.test.ts`):** Verifies that real audio streams flowing through VAD, speech segmentation, transcription, and candidate generation resolve to canonical scripture references with 100% precision and recall while discarding singing and musical chords.
  * **Automated Evaluation Script (`scripts/evaluate_pipeline.ts` / `pnpm run evaluate`):** Generates objective accuracy and latency reports:
    - Word Error Rate (WER) using Levenshtein distance
    - Reference Precision and Recall (target >= 95%)
    - Wrong-Suggestion Rate (target <= 5%)
    - Mean and peak processing latency
